# Говорящий двойник: речь готовым двойником — дизайн

Дата: 2026-08-22
Предшественники: `docs/superpowers/specs/2026-07-28-video-circle-double-design.md`
(этап 1, реализован), `docs/superpowers/specs/2026-08-06-video-circle-stage2-design.md`
(**устарел целиком** — построен на липсинке по снятым кружкам),
`docs/reference-video-avatar-engines.md` (замеры движков, рецепт образа),
`docs/plan-2026-08-07.md` (решение сменить цепочку), `kruzhochki.md` (журнал),
`dengi.md` (экономика).

## Задача

Двойник создаётся один раз. Дальше пользователь пишет текст выступления или
наговаривает его — и **готовый** двойник эту речь произносит. Пересоздавать
двойника ради каждого ролика нельзя: это и есть главное требование владельца.

Сегодня в боте есть только половина двойника — клонированный голос и
кружки-доноры (этап 1). Картинки, от которой отталкивается выбранный движок,
в боте нет вовсе, а сами ролики до сих пор делались вручную скриптами
на сервере.

## Что изменилось с 06.08 и почему спека этапа 2 выброшена

Замеры десяти движков живыми оплаченными прогонами 06.08 сменили класс движка.
Спека этапа 2 строила липсинк по снятым кружкам (`klingai:7@1`); все
липсинк-движки владелец забраковала («губы поехали», «губы съехали», «губы
очень узкие»). Утверждён **`klingai:avatar@2.0-standard`** — класс «аватар»:
**фото + звук → говорящее видео**, 270 ₽ за минуту.

Следствия для дизайна:

- исходник ролика — **картинка**, а не снятый кружок. Всё, что спека этапа 2
  писала про подгонку донора (`plan_donor_fit`, зацикливание, подрезка),
  выбрасывается;
- кружки-доноры остаются нужны, но только ради голоса и устного стиля;
- телеграмный кружок приходит 400×400, а Kling требует сторону 512–2160 —
  апскейл обязателен, вопреки утверждению старой спеки, что правок не требуется.

## Решения владельца (2026-08-22)

| Вопрос | Решение |
|---|---|
| Движок | `klingai:avatar@2.0-standard`, проверен и утверждён по соотношению цены и качества |
| Лицо и голос | уже есть у владельца, нужно перенести **в бота** |
| Образы | сменяются пользователем: **оба пути** — прислать готовую картинку и сгенерировать по описанию. Причёску менять словами **разрешено** |
| Звук при написанном тексте | **оба пути**: строим под свой голос, клон ElevenLabs включается настройкой позже |
| Доступ | весь вайтлист — он же список купивших подписку |
| Потолок | месячный лимит секунд рендера **на каждого пользователя** |
| Формат | пока только кружок (video note). Длинное видео — отдельная задача позже, **в том числе для сайта владельца** |
| Кнопка «сделай сценарий» | нужна |

## Границы

**Входит:** хранение лица и образов в боте, генерация образа по описанию,
приём речи текстом и голосом, необязательная переработка текста в устный
сценарий, синтез клонированным голосом (за настройкой), рендер говорящего
видео, приведение к формату video note, очередь заданий, превью в личку,
публикация в привязанный канал, месячный потолок расхода на пользователя.

**Не входит осознанно:**

- длинное видео и рилсы — отложено владельцем, задел оставлен колонкой `format`;
- видеообращения на сайте — отдельная задача, зависит от разведки по сайту
  (`plan-2026-08-07.md`, пункт 3);
- ежедневный ролик по расписанию — сначала надо убедиться, что качество
  проходит по живому каналу;
- автопубликация без утверждения — нет нигде и не будет;
- вебхук от Runware — воркер самодостаточен, вебхук добавляется сверху позже;
- self-host рендера — не окупается на текущих объёмах;
- площадки кроме Telegram.

## Из чего состоит двойник

| Составляющая | Хранение | Как заводится |
|---|---|---|
| **Лицо** — одна резкая фронтальная фотография | `avatar_faces`, одна строка на пользователя | пользователь присылает фото |
| **Образы** — картинки «одежда, место, свет», один активный | `avatar_looks`, много строк | прислать готовую картинку (0 ₽) либо описать словами и сгенерировать из лица через `google:4@1` (4 ₽) |
| **Голос** | `voice_profiles` + `avatar_donors` (этап 1, не переписываются) | голосовое на каждую речь; клон ElevenLabs — за настройкой |

Экран «Мой двойник» перестраивается:

```
Твой двойник: лицо — есть, образов — 3, активный «студия, белая рубашка»
[ 🎤 Сказать речь ]
[ 🖼 Образы ]  [ 📸 Заменить лицо ]
[ 🎙 Голос ]   [ 🗑 Удалить двойника ]
```

Существующие кнопки этапа 1 («Добавить кружки», «Удалить двойника»)
сохраняются: первая уезжает под «Голос», вторая остаётся на месте и теперь
стирает ещё лицо и образы.

«Голос» — это готовый экран этапа 1 без изменений: статус клона, сбор
кружков-доноров, пересоздание голоса. Новый код туда не добавляется, экран
просто получает своё место в новой раскладке.

### Два предупреждения, а не запрета

1. **Причёска.** Рецепт из `reference-video-avatar-engines.md` прямо запрещает
   менять причёску словами: модель «улучшает» длину и волну и уводит лицо.
   Владелец решила эту возможность оставить. Экран описания образа выводит
   предупреждение одной строкой; образ показывается на утверждение **до** того,
   как за него платят рендером, поэтому цена ошибки — 4 ₽, а не 135 ₽.
2. **Присланная готовая картинка не проверяется на композицию.** Первый
   забракованный `klingai:avatar` был забракован за общий план, а не за модель.
   Бот предупреждает про крупный план (голова и плечи во весь кадр), заставить
   не может.

Судить о сходстве может только владелец — это записано опытом трёх неудачных
образов и не меняется.

## Пользовательский сценарий

Вход один — кнопка `🎤 Сказать речь` на экране «Мой двойник». Если лица или
образа нет, бот ведёт их заводить, а не отказывает.

```
① РЕЧЬ — «напиши текст выступления или наговори его голосовым»
   │      [ Отмена ]
   │
   ├─ голосовое  →  это и есть готовая озвучка, 0 ₽ ────────┐
   │                                                         │
   └─ текст  →  бот показывает принятый текст:               │
        │       [ Озвучить как есть ]  [ Сделай сценарий ]   │
        │       [ Переписать ]  [ Отмена ]                   │
        │                                                    │
        └─ синтез клонированным голосом ─────────────────────┤
           (ключа ElevenLabs нет — бот отдаёт текст           │
            суфлёром: «наговори это голосовым»)               │
                                                              ▼
② ОЗВУЧКА — бот присылает звук обратно, его слышно            в подписке / 0 ₽
   [ Снять кружок ]  [ Перезаписать ]  [ Назад к тексту ]
   │
③ ОБРАЗ — картинка активного образа с подписью
   [ Снять с этим образом ]  [ Другой образ ]
   │
   «Снимаю, пришлю когда будет готово» — одно сообщение,
    редактируется на месте
   │
④ КРУЖОК — в личку                                            ~135 ₽ за 30 с
   [ Опубликовать в канал ]  [ Другой образ ]
   [ Переписать текст ]  [ Удалить ]
```

**Между приёмом речи и оплатой человек стоит дважды.** Послушать звук
бесплатно, посмотреть образ бесплатно; платит только шаг ④. Это главная
оптимизация расходов: платим не за ролик, а за неоплату брака.

**Поведение кнопок:**

- `Сделай сценарий` — текст пользователя переписывается под устную речь
  на его же расшифровках кружков (`style_examples.kind = 'spoken'`,
  собраны этапом 1). ~0,002 ₽. Результат показывается, исходный текст
  сохраняется, есть возврат к нему.
- `Перезаписать` — новый звук того же задания, образ не трогается.
- `Назад к тексту` — возврат на ①, кэш озвучки сбрасывается.
- `Другой образ` — список образов, пересобирается только рендер:
  аудио берётся из кэша задания и **не пересинтезируется**.
- `Переписать текст` — возврат на ①, образ не трогается.
- `Удалить` — задание закрывается, ролик не публикуется.

### Длина

Video note — не больше 60 секунд. Бот замеряет фактическую длительность звука
**до** оплаты: длиннее 60 с — отказ с предложением сократить, ноль расхода.
Целевая длина 30 секунд задаётся настройкой `AVATAR_TARGET_SECONDS`.

Порядок строго такой: сначала есть звук и его замеренная длительность, потом
рендер. Длительность синтеза по числу символов заранее не предсказывается.

### Ожидание рендера

Одно сообщение со статусом, редактируемое на месте. Не спамить: человека надо
отпустить, а не держать в чате. Явное «пришлю, когда будет готово».

Время рендера на 30 секундах **не замерено** — на пяти секундах было 213–520 с.
Это первое, что покажет живой прогон.

## Архитектура

### Правило границ

Шлюзы не знают про бота. Оркестратор не знает про aiogram. Хендлеры не знают,
какой движок под капотом. Благодаря этому смена движка — правка одного файла,
а тесты пайплайна пишутся без сети.

### Новые файлы

| Файл | Ответственность |
|---|---|
| `bot/services/avatar_gateway.py` | Говорящее видео за одним интерфейсом: `render(image_bytes, audio_bytes) -> task_uuid`, `poll(task_uuid) -> статус, результат, фактическая цена`. Знает разную форму входа у разных движков. Типизированные ошибки, ретраи, логирование — по образцу `ai_gateway.py` |
| `bot/services/look_prompt.py` | Чистая функция: описание словами → промпт образа по рецепту (крупный план, фронтальная поза, запрет «editorial fashion photography»). Без сети |
| `bot/services/video_note.py` | ffmpeg: апскейл образа до стороны ≥ 512, приведение результата к формату video note (квадрат, H.264 + AAC, `+faststart`, ≤ 60 с) |
| `bot/services/speech_pipeline.py` | Оркестратор: ведёт `speech_jobs` по статусам, зовёт шлюзы, считает деньги. Про aiogram не знает |
| `bot/services/speech_worker.py` | Фоновая очередь: опрос провайдера, постпроцесс, уведомление, уборка временных файлов |
| `bot/storage/avatar_faces.py` | Базовое лицо |
| `bot/storage/avatar_looks.py` | Образы и активный образ |
| `bot/storage/speech_jobs.py` | Задания рендера |
| `bot/storage/render_usage.py` | Счётчик секунд и денег по месяцам |

### Данные

**`avatar_faces`** — `telegram_id (PK), file_id, created_at`.
Одна строка на пользователя: лицо ровно одно, замена перезаписывает.

**`avatar_looks`** — `id, telegram_id, file_id, title, source ('uploaded' |
'generated'), prompt, is_active, created_at`. Активный образ ровно один
на пользователя; назначение нового снимает флаг с прежнего в той же транзакции.

**`speech_jobs`** — `id, telegram_id, source_text, script, look_id, audio_path,
audio_duration_sec, format, status, provider_task_id, result_file_id, cost_rub,
error, created_at, updated_at`.
Статусы: `draft → voiced → rendering → ready → published`, плюс `failed`
из любого. `format` пока всегда `video_note`.

**`render_usage`** — `telegram_id, usage_month, seconds_rendered, cost_rub`,
первичный ключ `(telegram_id, usage_month)`.

Задания живут в SQLite, **не в FSM**. Причина денежная: рестарт бота посреди
оплаченного рендера — это выброшенные 135 ₽. `audio_path` хранит кэш озвучки,
из-за которого «Другой образ» не пересинтезирует звук.

**Миграция.** Все четыре таблицы добавляются в `SCHEMA` и создаются на
развёрнутой базе через `CREATE TABLE IF NOT EXISTS`; существующие данные
не трогаются. Отдельной процедуры миграции не нужно — новых колонок в старых
таблицах нет (в отличие от `style_examples.kind` в этапе 1).

### Контракт провайдера

`POST https://api.runware.ai/v1`, тело — массив, первым элементом
`{"taskType": "authentication", "apiKey": "..."}`. Видео —
`taskType: "videoInference"`, асинхронно через `deliveryMethod: "async"`
и опрос `taskType: "getResponse"` по тому же `taskUUID`. `includeCost: true`
возвращает фактическую цену в поле `cost`.

Форма входа по движкам (получена разбором ошибок валидации, бесплатно):

| Движок | Поля входа |
|---|---|
| `klingai:avatar@2.0-standard`, `@2.0-pro` | `inputs.image` + `inputs.audio`, строкой |
| `heygen:avatar@4` | `inputs.image` + `inputs.audio`, строкой, не списком |
| `bytedance:5@2` | `inputs.image` + `inputs.audio` |

Образ: `taskType: "imageInference"`, модель `google:4@1`, `referenceImages` —
базовое лицо.

**Только base64** в формате `data:image/jpeg;base64,...` /
`data:audio/mpeg;base64,...`. Публичная ссылка на личное фото пользователя
не формируется никогда — это проверяется тестом.

### Очередь и воркер

Воркер — asyncio-задача, стартующая вместе с ботом. Раз в фиксированный
интервал опрашивает Runware по всем заданиям в статусе `rendering`. На старте
подбирает задания, оставшиеся в `rendering` с прошлого запуска, — рестарт
не сжигает оплаченный рендер.

По готовности: скачивает результат, прогоняет постпроцесс, отправляет кружок
в личку, записывает `result_file_id` и расход. `file_id` кэшируется — дальше
публикация в канал бесплатна и мгновенна.

Временные файлы живут в `TMP_MEDIA_DIR` и удаляются по завершении задания.
Существующий `media_cache.py` не годится: он жёстко пишет `.jpg` и не чистит
за собой.

## Деньги и доступ

**Доступ** — вайтлист, он же список купивших подписку. Отдельной сущности
подписки не заводим: её в боте нет, а вводить её ради одной кнопки — работа
не по этой задаче.

**Потолок** — `AVATAR_MONTHLY_SECONDS_LIMIT = 300` на каждого пользователя:
10 кружков по 30 секунд, ~1350 ₽. Потолок в **секундах рендера**, а не
в запросах: `RateLimitMiddleware` считает обращения, здесь важны деньги.
Проверка — до обращения к провайдеру. Списание — по факту успешного рендера,
из поля `cost` в ответе. Неудавшийся рендер не списывается.

**Образ за 4 ₽** пишется в `cost_log` и виден в `/costs`, но дневной
картиночный лимит (`image_usage_log`) не расходует: смена одежды не должна
упираться в бюджет на картинки к постам. Отдельного потолка на образы нет —
4 ₽ пренебрежимы, а генерация всегда требует явного нажатия.

Курс пересчёта — существующий `_USD_RUB` в `cost_tracker.py`.

## Обработка ошибок

| Ситуация | Поведение |
|---|---|
| Бот перезапустился во время рендера | Воркер подбирает `rendering` на старте и продолжает опрос |
| Рендер упал или таймаут | `failed`, кнопка «Повторить». Звук и образ сохранены — повтор стоит один рендер |
| Синтез речи упал | Задание остаётся в `draft`, рендер не запускался, ничего не оплачено |
| `ELEVENLABS_API_KEY` пуст | Путь «написать текст» отдаёт суфлёр вместо синтеза; бот при старте не падает |
| Звук длиннее `AVATAR_MAX_SECONDS` (60) | Отказ до оплаты с предложением сократить |
| Лица нет | Предложение прислать фотографию |
| Образа нет | Предложение прислать картинку или описать образ словами |
| Канал не привязан | Кнопка публикации не показывается |
| Месячный лимит исчерпан | Отказ до обращения к провайдеру, ноль расхода |
| Результат не влезает в формат video note | Постпроцесс приводит к формату; при невозможности — ошибка до отправки |
| Пользователь в режиме сбора шлёт не то | «Отмена» есть на каждом экране сбора. Ловушка `CircleStates.collecting_donors`, где бот на фотографию отвечал «жду кружок» и терял её, не повторяется |

Конвенции проекта: pytest, `AsyncMock`, хендлеры вызываются напрямую, реальный
