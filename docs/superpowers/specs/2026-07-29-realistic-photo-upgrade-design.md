# Кнопка «Сделать реалистичнее» — дизайн

Дата: 2026-07-29

## Задача

Бот генерирует картинки через vsegpt.ru двумя способами: под уже написанным
постом (`bot/handlers/refine.py::on_refine_image`) и отдельным пунктом меню
«Картинка от ИИ» по текстовому описанию
(`bot/handlers/start.py::on_photo_gen_description`). Дефолтная модель —
дешёвый `img-flux/flux-2-klein-4b`, специально возвращённый после того, как
более дорогой `img-flux/pro1.1` (~15₽/картинку) стал дефолтом и незаметно
для владельца исчерпал баланс на vsegpt.ru.

Нужна возможность осознанно, за дополнительную известную заранее плату,
получить более реалистичную версию уже сгенерированной картинки — без
риска случайно потратить деньги по умолчанию.

## Пользовательский сценарий

```
[любой из двух путей генерирует картинку дешёвой моделью]
   │
   ▼  бот присылает фото с подписью image_preview_caption
      и клавиатурой из одной кнопки:
      [ 🎨 Сделать реалистичнее (~15₽) ]
   │
   ├─ пользователь не жмёт → ничего не происходит, доп. расходов нет
   │
   └─ пользователь жмёт
        │
        ▼  бот перегенерирует тот же промпт через img-flux/pro1.1,
           присылает результат ОТДЕЛЬНЫМ новым сообщением (обе картинки
           остаются в чате — пользователь сравнивает и решает, что
           использовать) с подписью "✨ Более реалистичная версия"
        │
        ▼  кнопка на первом сообщении заменяется на "✅ Готово"
           (не активна) — защита от повторного клика/двойного списания
        │
        └─ если AI Gateway вернул ошибку (нет баланса и т.п.) —
           кнопка остаётся кликабельной, пользователю показывается
           то же понятное сообщение об ошибке, что и при обычной
           генерации (существующий _AI_ERROR_KEYS)
```

Апгрейженная картинка становится новым `pending_media` (как и обычная) —
именно она уйдёт при публикации в канал, если её сгенерировали последней.

## Что уже есть в проекте (переиспользуем)

- `bot/services/ai_gateway.py::generate_image(prompt, model=None, size=None)`
  — уже принимает `model` явно, никаких изменений в самой функции не нужно.
- `bot/handlers/content.py::_AI_ERROR_KEYS` — маппинг исключений AI Gateway
  на ключи локализации, уже используется в обоих местах генерации.
- `bot/storage/users.py::set_pending_media` — уже вызывается после каждой
  успешной генерации, паттерн переиспользуется без изменений.
- FSM state (`state.update_data` / `state.get_data`) — уже используется в
  обоих хендлерах для `language` и других данных сессии.

## Архитектура

### Новая конфигурация

`bot/config.py`:
```python
DEFAULT_AI_GATEWAY_PREMIUM_IMAGE_MODEL = "img-flux/pro1.1"
```
Новое поле `Settings.ai_gateway_premium_image_model`, читается из
`AI_GATEWAY_PREMIUM_IMAGE_MODEL` (по умолчанию — значение выше). Отдельная
переменная от `AI_GATEWAY_IMAGE_MODEL` — дефолтную модель для обычной
генерации можно будет снова менять, не трогая эту кнопку.

### Хранение промпта для повторной генерации

Причина: к моменту клика на «Сделать реалистичнее» исходное сообщение с
текстом поста (или описанием) обычно уже не то, что открыто у
пользователя — под картинкой его нет. Промпт, переданный в
`generate_image()`, сохраняется в FSM-данные сразу после
`generate_image_prompt()`:
```python
await state.update_data(last_image_prompt=image_prompt)
```
в обоих хендлерах (`on_refine_image` и `on_photo_gen_description`).

### Новый callback и клавиатура

`bot/keyboards/refine.py` (переиспользуем модуль, не плодим новый):
```python
CALLBACK_IMAGE_UPGRADE = "img:upgrade"

def build_image_upgrade_keyboard(lang: str) -> InlineKeyboardMarkup:
    ...  # одна кнопка "🎨 Сделать реалистичнее (~15₽)"

def build_image_upgraded_keyboard(lang: str) -> InlineKeyboardMarkup:
    ...  # одна неактивная кнопка "✅ Готово" (callback на no-op либо просто
         # текстовая замена через edit_message_reply_markup)
```
Обе картинки (обычная и upgrade) уже отправляются как `bot.send_photo(...)`
— добавляем `reply_markup=build_image_upgrade_keyboard(language)` к первой.

### Новый хендлер

`bot/handlers/refine.py` (единая точка — оба места генерации ведут сюда,
т.к. промпт и язык уже унифицированно лежат в FSM state):
```python
@router.callback_query(F.data == CALLBACK_IMAGE_UPGRADE)
async def on_image_upgrade(callback, state, db_path, bot) -> None:
    # 1. читает last_image_prompt из state, language
    # 2. whitelist/limit-проверки — как у обычной генерации
    # 3. generate_image(prompt, model=settings.ai_gateway_premium_image_model)
    # 4. send_photo новым сообщением, caption "✨ Более реалистичная версия"
    # 5. set_pending_media(...) на новый file_id
    # 6. increment_usage(...)
    # 7. edit_message_reply_markup(callback.message, build_image_upgraded_keyboard(...))
    # 8. при AIGatewayError — тот же _AI_ERROR_KEYS, кнопку НЕ трогаем
```
Апгрейд тратит дневную/месячную квоту так же, как обычная генерация
(симметрично существующей проверке в `on_refine_image`).

### Локализация

Новые строки в `bot/locales/{ru,en,vi,zh}.py`:
- `image_upgrade_button` — «🎨 Сделать реалистичнее (~15₽)»
- `image_upgraded_button` — «✅ Готово»
- `image_upgraded_caption` — «✨ Более реалистичная версия»

## Границы (осознанно не делаем)

- Не редактируем/не удаляем исходную дешёвую картинку — обе версии
  остаются в чате, пользователь сам решает, что использовать.
- Не добавляем подтверждающий диалог («точно потратить 15₽?») — цена уже
  видна в тексте самой кнопки, это и есть подтверждение.
- Не делаем цену в кнопке динамической/из реального прайса vsegpt.ru —
  захардкоженное «~15₽» в локали, как приблизительный ориентир. Если
  реальная цена модели изменится, это правится вручную в локалях (как и
  сама модель — не автоматизируем то, что меняется раз в несколько месяцев).
- Не переиспользуем это для будущих `img-flux/kontext-*` (image-to-image
  редактирование по референсу) — отдельная фича, если понадобится.
