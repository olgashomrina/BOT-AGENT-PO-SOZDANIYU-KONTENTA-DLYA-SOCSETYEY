# Авторский пост из дайджеста — дизайн

Дата: 2026-07-28

## Задача

После выдачи дайджеста бот показывает вторую кнопку — **«✍️ СОЗДАЙ МОЙ АВТОРСКИЙ ПОСТ»**.
По ней запускается сценарий: пользователь выбирает пункт дайджеста, отдаёт боту
образцы своих постов, бот считывает личный почерк и пишет пост с хэштегами
в этом стиле.

## Что уже есть в проекте

Фича почти целиком собирается из отлаженных кусков:

- `bot/storage/style_examples.py` — таблица образцов стиля, лимит на пользователя,
  вытеснение старых.
- `bot/handlers/settov.py` (`/settov`) — сбор образцов по одному сообщению.
- `bot/services/content_generator.py` — `build_prompt()` уже принимает
  `style_examples` и вклеивает их в промпт.
- `bot/handlers/content.py::_send_variants` — рассылка вариантов с кнопками доработки.
- `bot/handlers/refine.py` — «Ещё / Короче / Опубликовать / Картинка / На сайт»;
  перегенерация читает `source_text` и `content_language` из FSM-данных.

## Пользовательский сценарий

```
[дайджест выдан]
   ├─ 🔄 Собрать дайджест по другой теме        (существует)
   └─ ✍️ СОЗДАЙ МОЙ АВТОРСКИЙ ПОСТ              (новая)
        │
        ▼  «По какому пункту дайджеста написать пост?»
        [1] [2] [3] [4]
        [5] [6] [7] [8]
        │
        ▼  «Отлично, берём: <заголовок пункта>»
        [ Помогу тебе написать, жми дальше ]
        │
        ├─ образцов < 5 → «Вставь образцы своих постов, не менее 5-ти.
        │                   Присылай их подряд, по одному в сообщении.»
        │                   счётчик «Принято N из 5»
        │                   с 5-го: + [ Готово, пиши пост ] (можно дослать до 10)
        │
        └─ образцов ≥ 5 → «Я уже знаю твой почерк — сохранено N образцов.»
                          [ Писать сразу ]  [ Загрузить новые образцы ]
        │
        ▼  «Куда пишем?»   [ Telegram ]  [ VK ]  [ И туда, и туда ]
        │
        ▼  3 варианта авторского поста с хэштегами на каждую выбранную
           площадку, каждый — с существующей клавиатурой доработки
```

### Нумерация пунктов

Сквозная, в порядке вывода дайджеста: новости (до 4) → статьи (до 3) →
«новые методики» (0 или 1). Максимум 8 пунктов, кнопки раскладываются
по 4 в ряд.

Блок «новые методики» — синтезированный ботом текст, а не ссылка. Он тоже
выбираем: для авторского поста это часто самый интересный материал.

### Счётчик образцов

Счётчик показывает **общее количество образцов в хранилище**, а не число
присланных за сессию. Пользователь с 2 сохранёнными образцами после первого
нового сообщения увидит «Принято 3 из 5». Так «не менее 5-ти» означает
«у бота есть 5 образцов твоего стиля», а не «пришли 5 прямо сейчас».

### Границы

- Кнопка появляется только под дайджестом, запрошенным **вручную**. Ежедневный
  дайджест от планировщика (`bot/services/digest_scheduler.py`) уходит вне
  диалога, FSM-состояния для него нет. Осознанно вне этой задачи.
- Генерация тратит дневную/месячную квоту; проверки вайтлиста и лимита — на
  шаге выбора площадки, до вызова AI. Сбор образцов квоту не тратит.

### Передача выбранного пункта

В `callback_data` Telegram влезает 64 байта — заголовок новости туда не
поместится. Поэтому кнопка несёт только индекс (`authorpost:item:3`), а сам
список пунктов лежит в FSM-данных под ключом `digest_items`.

Выбранный пункт пишется в FSM-данные как `source_text` — тот же ключ, что
использует `bot/handlers/refine.py`. Благодаря этому кнопки доработки под
авторскими вариантами работают без отдельного кода.

### Флаг хэштегов в FSM

`with_hashtags` живёт в FSM-данных, чтобы перегенерация в `refine.py` знала,
нужны ли хэштеги. Авторский сценарий выставляет его в `True`; обычный
сценарий (`content.py::_finish`) выставляет **в `False` явно**, а не оставляет
как есть — иначе флаг от прошлого авторского поста протёк бы в обычную
доработку и хэштеги вылезли бы там, где их не просили.

### Попутные исправления

Три правки, без которых фича вела бы себя непоследовательно:

1. **`refine.py` теряет авторский стиль.** `_generate_and_send()` вызывает
   `generate_variants()` без `style_examples` — «Ещё вариант» уже сегодня
   возвращает текст не в стиле пользователя, хотя исходные варианты были в
   стиле. Для авторского поста это ломает саму суть фичи. Чинится чтением
   образцов из БД (как в `content.py`) и флага `with_hashtags` из FSM-данных.
2. **`_send_variants` становится публичной** — её вызывает и новый роутер.
3. **Лимит образцов 5 → 10.** При требовании «не менее 5» потолок ровно в 5
   не оставляет запаса. Побочный эффект: в обычную генерацию тоже пойдёт до
   10 образцов — промпт длиннее, стиль точнее.

### Известное ограничение

FSM-хранилище — `Dispatcher()` без аргументов, то есть `MemoryStorage`
в памяти процесса (`bot/main.py`). При перезапуске бота между выдачей
дайджеста и нажатием кнопки `digest_items` пропадает. Обрабатывается
сообщением «дайджест устарел, собери свежий», а не исключением. Переезд на
постоянное хранилище — отдельная задача, сюда не входит.

## Обработка ошибок

| Ситуация | Поведение |
|---|---|
| `digest_items` нет в FSM (перезапуск бота) | «Дайджест устарел, собери свежий» + кнопка сбора |
| Индекс пункта вне диапазона (кнопка от прошлого дайджеста) | То же сообщение, без `IndexError` |
| Нетекстовое сообщение на шаге сбора образцов | Просьба прислать текст, счётчик не растёт |
| Образец длиннее 2000 символов | Отказ (как в `/settov`), счётчик не растёт |
| Пользователь не в вайтлисте | Отказ до вызова AI |
| Исчерпан дневной/месячный лимит | Отказ до вызова AI |
| `AIGatewayError` при генерации | Сообщение по существующей таксономии, квота не списывается |

## Тестирование

### Новый файл `tests/test_handlers_authorpost.py`

Конвенции проекта: pytest + `AsyncMock`, хендлеры вызываются напрямую,
реальный `FSMContext` на `MemoryStorage`, БД — фикстура `db_path`.

Счастливый путь:

- кнопка «АВТОРСКИЙ ПОСТ» показывает ровно N кнопок по числу пунктов дайджеста
- выбор пункта кладёт его текст в `source_text` FSM
- «жми дальше» при пустом хранилище → приглашение + состояние `collecting_examples`
- образцы 1-4 → счётчик «принято N из 5», кнопки «Готово» ещё нет
- 5-й образец → кнопка «Готово, пиши пост» появилась
- выбор площадки → `generate_variants` вызван с нужным `platform`, с образцами
  и `with_hashtags=True`; «И туда, и туда» → два вызова

Развилка сохранённых образцов:

- ≥5 сохранённых → показана развилка, шаг сбора пропущен
- «Загрузить новые» → старые стёрты, счётчик с нуля

Плохие пути: по таблице «Обработка ошибок» выше — по тесту на строку.

### Правки в существующих тестах

- `tests/conftest.py` — новый роутер в `_SINGLETON_ROUTERS` (иначе падения,
  зависящие от порядка сборки тестов)
- `tests/test_content_generator.py` — `with_hashtags=True` добавляет инструкцию;
  `False`/по умолчанию оставляет промпт байт-в-байт прежним
- `tests/test_storage_style_examples.py` — потолок 10; `clear_style_examples()`

- `tests/test_handlers_refine.py` — «Ещё»/«Короче» прокидывают образцы и флаг
- `tests/test_handlers_content_flow.py` — обычный сценарий сбрасывает

- `tests/test_localization.py` — новые ключи во всех 4 языках
- `tests/test_keyboards_start.py` — под дайджестом две кнопки
