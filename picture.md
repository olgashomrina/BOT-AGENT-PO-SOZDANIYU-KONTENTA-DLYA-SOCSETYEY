- `img-ideogram/v3`, `img-recraft/v3` — сильны в тексте на картинке/дизайне, не в первую очередь для "фото людей".

### Деплой (2026-07-25)

- Владелец подтвердил: платный тариф "Профессиональный" на vsegpt.ru оплачен.
- Закоммичено (`6bcb2da` "Switch default image model to FLUX1.1 Pro for realism") и запушено в `olgashomrina/feature/mvp1-bot`.
- GitHub Actions CI/CD (Phase 16) был приостановлен на этапе настройки секрета `DEPLOY_SSH_KEY` и никогда не был подтверждён живьём — не стал на него полагаться. Задеплоил напрямую по SSH, как в предыдущих сессиях (та же схема, что для Phase 10/13).
- По пути обнаружена и обойдена техническая проблема: `ssh`/`git bash` на этой машине не может корректно открыть `~/.ssh/known_hosts`, когда путь к домашней папке содержит кириллицу (`C:\Users\Лина Иващенко`) — ssh получает путь в битой кодировке и падает с "Host key verification failed", хотя ключ и известный хост на самом деле корректны. Решение: передавать `-o UserKnownHostsFile="\"$HOME/.ssh/known_hosts\""` (с внутренними кавычками, которые видит именно ssh, а не bash) при каждом SSH-вызове на этой машине.
- На проде переменная `AI_GATEWAY_IMAGE_MODEL` в `.env` явно не задана (проверено через `grep -c`, значение не смотрели) — значит подхватился новый дефолт из кода само собой, без правки `.env` на сервере.
- На сервере: `git pull` (fast-forward `fc43e9a → 6bcb2da`) → `.venv/bin/pip install -r requirements.txt` → `systemctl restart content-bot`. Сервис поднялся чисто (`systemctl is-active` → `active`), в логах только штатный SIGTERM/restart и "Бот запускается (long polling)", ошибок нет.

### Баг после деплоя: "не удалось получить корректный ответ" (2026-07-25)

- Владелец протестировал генерацию картинки дважды подряд — оба раза одна и та же ошибка.
- **Диагностика (systematic-debugging):** прочитал логи прода (`journalctl -u content-bot`) за оба вызова — оба дали идентичную ошибку, не флуктуирующую, значит не флейки/таймаут, а детерминированная причина.
- **Корневая причина (не баг в коде бота):** аккаунт на vsegpt.ru имеет "soft limit per query" (мягкий лимит стоимости одного запроса) = 10.000, а `img-flux/pro1.1` стоит ~14.9 за картинку → vsegpt.ru отклоняет запрос с HTTP 400: `Exceeded soft user limit per query: 1490->700, expected price 14.9, but your limit is 10.000`.
- Это отдельная настройка от общего баланса/тарифа "Профессиональный" — тариф оплачен и не блокирует, блокирует именно лимит на один запрос, который настраивается на https://vsegpt.ru/User/SettingsModels.
- **Фикс — не в коде, а в настройках аккаунта vsegpt.ru:** владельцу нужно зайти на https://vsegpt.ru/User/SettingsModels и поднять лимит "цена за запрос" выше 14.9 (например, до 20-50), тогда `img-flux/pro1.1` начнёт проходить. После этого повторный тест генерации в боте должен сработать без изменений кода.
- Код `bot/services/ai_gateway.py` отработал штатно: поймал ошибку 400 от прокси, залогировал её понятно (`AIGatewayInvalidResponseError`), пользователю ушло сообщение об ошибке вместо падения бота — исправлять там нечего.
